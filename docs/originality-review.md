# Spec-to-Quality (S2Q) — Originality Review

> **Status:** Phase 1 draft awaiting review. Prepared 2026-11-14 using web search, publisher pages and the arXiv API. **This is not a systematic literature review.** No database-wide, protocol-driven search (e.g., Scopus, ACM DL, IEEE Xplore with documented queries and screening) was performed. Any statement of the form "we did not find …" means *we did not find it with this search*, not that it does not exist. A fresh search must be repeated immediately before publication (roadmap Phase 7).

## 1. How sources were verified

- Every URL cited below was requested on 2026-11-14 (HTTP status check with a browser-like user agent, or fetched through a web-fetch tool). Status: **resolved (200)** unless noted in §7.
- arXiv entries: title, authors, date and abstract were read from the arXiv API; **only abstracts were read for most arXiv papers**, not the full texts. Claims about a paper are limited to what its abstract (or, where stated, full text) says.
- Full text read: Sacouto et al. 2026 [D3] and Caporusso & Perdue 2025 [D4] (ISCAP papers); METR's Feb-2026 post [P2]. Everything else: abstract/summary level only.
- Preprints are not peer reviewed unless stated. Vendor reports (Sonar, Veracode) are labelled as vendor sources.
- Later-dated arXiv identifiers (26xx) exist in the arXiv API as of the check date; they were taken at face value as listed there.

## 3. Comparable experiments — what is closest to S2Q

No single prior work in our search covers the entire chain. The nearest neighbours, and what each lacks relative to S2Q:

1. **Sonar's own LLM comparisons [S1, S2, S15]** — SonarQube-based, multi-model, but task/assignment-level (not an application built from one specification), vendor-authored or vendor-affiliated, and (from what we can see) without a bounded remediation stage or a cost-to-gate economic model.
2. **SDD matched comparison [D3]** — controlled, with token/time cost, but measures functional pass rate on small benchmark tasks; no static-analysis quality or remediation.
3. **In-the-wild PR studies [S6, S8, S9]** — large and realistic, but observational; can't control specification or model; no cost-to-gate.
4. **Static-warning repair [R1, R3, R2]** — evaluate repair techniques (including iterative LLM fixing), not the downstream economics of choosing a cheaper generator.
5. **End-to-end generation benchmarks [B7–B10]** — evaluate functional completion for full projects, not static quality or remediation cost.
6. **Backend generation benchmark [S13]** — correct *and* secure, but dynamic security checks, no maintainability/remediation/cost chain.

## 4. Research gaps (as observed in this limited search)

- **G-1. Chain-level evidence.** We did not find a study that follows **one frozen engineering specification → multiple coding models (price tiers) → fully built application → pinned static analysis → bounded remediation to a predefined gate → measured total cost**.
- **G-2. Cost-to-gate as an outcome.** Token and dollar cost is reported in some studies (e.g., D3, B11) but we did not find *cost to reach a quality gate*, including right-censoring for runs that never reach it, as a primary outcome.
- **G-3. Repeated trials on application-scale generation.** Many studies report single runs per model or per task; application-scale repeated-trial variance by model is less commonly reported in what we found (this is a weak statement — we did not audit methods sections).
- **G-4. Model–harness separation in a code-quality study.** Harness-confound papers [G1–G4] study task success on terminal/coding benchmarks; we did not find them applied to *static-quality and remediation cost*.
- **G-5. Estimated vs measured remediation effort.** Studies using Sonar's estimated effort [S7] treat it as an indicator; we did not find designs that set it against *measured* agent/human remediation effort.
- **G-6. Gate-gaming controls in LLM remediation studies.** We did not find explicit integrity checks for suppression/exclusion gaming in the remediation work we read (abstract-level; may exist in full texts).

## 5. Potential original contributions (hedged)

If, after the Phase 7 re-check, the gaps above still hold, S2Q's *potential* contributions are:

1. **A reproducible protocol** linking specification, model, generated application, static analysis, remediation and cost in one experiment (the chain, not the individual links).
2. **Cost-to-gate with censoring-aware economics** and a breakeven sensitivity view for engineering leaders.
3. **A paired estimated-vs-measured remediation effort analysis.**
4. **A model-plus-harness disclosure design** applied to code-quality outcomes.
5. **Gate-integrity controls** (anti-suppression checks) as part of the remediation protocol.
6. **Open raw data** for repeated application-scale generation across price tiers.

## 7. Limits of novelty claims

- Search was web-based and not systematic; recent work (especially 2026 preprints) appears quickly, and some may not be indexed in what we saw.
- We read **abstracts only** for most arXiv entries. A paper's full text could include analyses (e.g., remediation, cost) that its abstract does not mention.
- Vendor reports (Sonar, Veracode, possibly CodeScene) may contain unpublished methodology details.
- Unverified sources, stated plainly:
  - **T2 (Just et al., FSE 2014):** neither the University of Washington PDF URL nor the ACM DOI resolved from our environment; cited from memory/search only.
  - **B5 (OpenAI) and the ACM DOI of Arcuri & Briand [T1]:** direct curl returned HTTP 403; the pages themselves were read through a web-fetch tool (OpenAI) or an alternative ICSE page (T1).
  - **S14 (Veracode) and B6 (METR note):** pages resolve; their specific numbers/findings were not extracted, so none are quoted here.
  - **S2 / S10 / R2 affiliations:** author affiliations (possible Sonar or CodeScene ties) were not verified; check before describing these papers as vendor-independent.
  - **Mistral and Qwen model IDs:** see model-selection.md; the Mistral API model ID string was not confirmed on the pricing page and no Qwen ID was verified.
- "Novel" must not be asserted in the article without a refreshed search and without citing the nearest works above.
- This project's tooling vendor (Sonar) also publishes LLM comparisons; S2Q is independent of Sonar and receives no support from it (to be declared in the final report).
